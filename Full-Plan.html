MISSION STATEMENT
Build a free, public, web-only Bloomberg-style intelligence terminal for Indonesian equities (IDX). The platform's singular purpose is to detect insider accumulation, smart money flows, and broker clustering before the market realizes. This is not a stock dashboard. It is an asymmetric intelligence weapon for Indonesian traders — dense, institutional, and brutally signal-focused.
AGENT CLASSIFICATION SYSTEM
FAST 14 agents
Assigned to scaffolding, UI components, configuration, export utilities, and any task with a clear, bounded specification. Speed is the priority. Context windows: 8K–16K tokens. Do not assign FAST agents to logic that touches scoring, detection, or data parsing.
PRO 16 agents
Assigned to core engineering: scrapers, schedulers, API endpoints, database integrations, and feature modules. Balanced speed + quality. Context windows: 32K–64K tokens. PRO agents own the data pipelines and all FastAPI route logic.
HEAVY 8 agents
Reserved exclusively for correctness-critical reasoning: scoring models, bandar detection, AI integration, and QA validation. Do not use HEAVY agents for scaffolding. Context windows: 64K–200K tokens. Every HEAVY output requires a QA gate before merge.

TRACK B — SIGNAL ENGINES (all parallel, depend only on DB schema being deployed)
PRO BROKER-FLOW-01 Context: 64K tokens · Weeks 5–8
Build the broker net flow aggregation engine. This produces the most actionable signal in the terminal: which brokers are accumulating or distributing, and at what magnitude.
Algorithm Specification
  • 3-Day Rolling Net Flow: For each (stock, broker), compute: net_flow_3d = SUM(net_value) for last 3 trading days. Store the result in a materialized view or computed table refreshed every 15 min.
  • Z-Score Normalization: For each broker code, compute the mean and stddev of their net_flow_3d across all stocks over the last 60 trading days. Then: z_score = (net_flow_3d - mean) / stddev. A z-score > 2.0 is a statistically significant accumulation event.
  • Broker Cluster Detection: If 2+ brokers show z-score > 1.5 in the same stock within the same 3-day window, flag as a broker_cluster. Write to the broker_clusters table.
  • Market-Level View: Produce a leaderboard of the top 20 stocks by absolute broker net flow (|net_value_3d|) across all brokers. This powers the TOPBUY command.
  • Stealth Score: Compute stealth_ratio = |net_value_3d| / volume_idr_3d. A low stealth_ratio (<0.3) with high net flow indicates stealth accumulation — price has not moved proportionally to flow. This feeds into the conviction score.
# Core SQL query for broker net flow score WITH recent_flows AS ( SELECT stock_id, broker_code, SUM(net_value) AS net_flow_3d, SUM(buy_value + sell_value) AS total_activity FROM broker_transactions WHERE date >= CURRENT_DATE - 3 GROUP BY stock_id, broker_code ), stats AS ( SELECT broker_code, AVG(net_flow_3d) AS mean_flow, STDDEV(net_flow_3d) AS std_flow FROM recent_flows GROUP BY broker_code ) SELECT r.*, (r.net_flow_3d - s.mean_flow) / NULLIF(s.std_flow, 0) AS z_score FROM recent_flows r JOIN stats s USING (broker_code)
PRO VOL-ANOMALY-01 Context: 48K tokens · Weeks 5–8
Build the volume anomaly detection engine. Unusual volume is one of the earliest precursors to informed trading activity.
Algorithm Specification
  • Baseline: For each stock, compute the 20-day average daily volume (ADV20). Exclude circuit-breaker days (volume = 0 or >5× previous day).
  • Anomaly Threshold: Flag a day as anomalous if: volume > 2.5 × ADV20 (HIGH) or volume > 1.8 × ADV20 (ELEVATED). Store the multiplier as volume_sigma in the signals table.
  • Price-Volume Divergence: Flag "stealth" days where volume_sigma > 2.5 but |price_change_pct| < 1.0%. This is a particularly strong signal — high volume without price movement suggests controlled accumulation.
  • Run Length: Count consecutive days above 1.5× ADV20. A run of 3+ days is a stronger signal than a single spike.
  • Write results to the signals table with signal_type = 'VOL_ANOMALY'. Include volume_sigma, run_length, and stealth_flag in source_ids (JSONB).

PM STANDING ORDERS
Non-Negotiable Rules for All Agents
Data Integrity
Never display unverified data. If confidence < 0.7, show a ⚠ indicator.
Every number shown to users must trace back to a specific Supabase row.
Scrapers fail loudly into logs. They never silently insert wrong data.
Deduplication is mandatory on every table that accepts scraped input.
The hash_dedup pattern is the standard. Every scraper must implement it.
UX Philosophy
Tables are primary. Charts are secondary. Never let a chart push a table off-screen.
Every page must be reachable via a terminal command. No page exists without a command.
Dense information is not clutter. Whitespace is not free — it costs signal density.
Speed is a feature. Command palette response <150ms. API response <800ms p95.
No login. No registration. No paywalls. Ever. This is a public intelligence tool.
Cost Discipline
Every agent must know their monthly request budget. Track it. Report it.
No websockets. Polling with caching is sufficient and dramatically cheaper.
NVIDIA AI calls are on-demand only — never batch-generate summaries.
Cloud SQL is explicitly forbidden. Supabase free tier is mandatory.
If a feature requires a paid API, reject it. Find a free alternative or descope.
Agent Coordination
HEAVY agents write specs; PRO agents implement them. Never the reverse.
Every HEAVY output gets a paired QA agent before it ships to production.
FAST agents do not touch scoring logic, parser logic, or detection rules.
Blocking dependencies are 7. Resolve them in order. Nothing else blocks launch.
ARCH-REVIEW-01 runs at end of Phase 2 and end of Phase 4. Not optional.
Legal & Compliance
All data sourced from public IDX and KSEI regulatory disclosures only.
No personal data stored. No user tracking. No cookies except essential.
Bandar signal narratives must not imply illegal activity — "unusual pattern" not "manipulation".
Methodology page is mandatory at /methodology before public launch.
Disclaimer: "For informational purposes only. Not investment advice."
